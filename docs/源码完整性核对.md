## 二、构建脚本路径修复（v2.8.1）

协议头实际位置是 `src/dashcast_proto/`，但所有构建脚本仍指向旧的 `src/`。已修：

| 脚本 | 修正 |
|---|---|
| `src/ap/build-ap.ps1` | `$PROTO` → `$HERE\..\dashcast_proto` |
| `src/ap-native/build-dcapd2.ps1` | `-I "$HERE\..\dashcast_proto"`；`$HERE` 改脚本自身目录 |
| `src/ap-native/build-dcapd2.bat` | 同上 |
| `src/ap-native/build-dcapd.ps1` | `$HERE` 改脚本自身目录（去掉硬编码盘符） |
| `src/cp/build-dashcastd.sh` | `-I$HERE/../dashcast_proto` |
| `src/cp/build-ldemo.sh` | 同上，`$HERE` 改相对定位 |

> 修前 `build-ap.ps1` 的 `PROTO` 会解析成 `src/src`，`build-dcapd2.ps1` 找不到 `dashcast_proto.h` —— 包内无法重编。

## 四、包内文件布局（与旧文档的目录树不同）

文档里写的 `dashcast/src/...`、`dashcast/cp/...`、`dashcast/ap/...` 是**旧仓库布局**。移交包实际是：

```
dashcast-handover-2026-10-30/
├── README.md                      # 版本演进 + 实测数据（到 v2.8）
├── HANDOVER.md                    # 主交接文档
├── docs/
│   ├── transport-codec-plan.md    # H.264 可行性与压测记录
│   ├── 投屏卡死修复说明.md         # v2.8.2 卡死机理与排查指标 ★新增
│   └── 源码完整性核对.md           # 本文件 ★新增
├── src/
│   ├── dashcast_proto/            # ★协议唯一真身（不是 src/ 根下）
│   │   ├── dashcast_proto.h
│   │   └── lz4mini.h
│   ├── cp/                        # CP 侧：dashcastd + h264rx + sysroot + openh264
│   ├── ap/                        # APK 工程（Java + libdcap.so 源码）
│   ├── ap-native/                 # dcapd2 / h264enc / 历史 dcapd 与 stubs
│   └── cpbench/                   # 压测安全契约（bench.sh + README）
└── artifacts/                     # 三件套 + MD5SUMS.txt
```
