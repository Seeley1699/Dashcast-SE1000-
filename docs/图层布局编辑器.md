# 可视化图层布局（v2.9，2026-10-30）

> 在仪表上叠加一层**带形状的透明膜**：圆角矩形 / 梯形 / 椭圆，可加圆角、羽化、边框。
> 形状外 alpha=0 → 合成器把原厂仪表透出来；形状内 alpha=255 → 盖住它。
> 这就是 README 里反复强调的 EVCC 原理："不替换、不破坏底层仪表"，只叠一层膜。

---

## 一、入口

App 主界面 →「投屏控制」卡片 →**「图层布局（圆角 / 梯形 / 羽化）」**。

编辑器分三块：

```
┌────────────────────────────────────────────┐
│ 可视化布局编辑器（拖拽 / 网格 / 形状 / 圆角）  │
├────────────────────────────────────────────┤
│  ▓▓▓▓ 预览区（网格 + 图层形状 + 右下拖拽柄） ▓▓ │
│  1920 × 532 · (x, y)　图层 w × h　已生效/未启用 │
├────────────────────────────────────────────┤
│ 形状与网格   [形状：圆角矩形] [放大编辑]        │
│   网格       ─────●────────  32px            │
│   DPI        ──●──────────  160              │
│ 边框与圆角                                      │
│   边框        ●──────────   0                │
│   左上/右上/左下/右下圆角  ──●────  24°        │
│ 梯形与羽化                                      │
│   梯形上沿 / 梯形下沿 / 羽化  ─●──  0          │
│ 应用到仪表                                     │
│   [遮罩已关闭（点击启用）] [恢复全屏]           │
│ 提示：形状依赖透明通道，只在 BGRA+LZ4 档生效…   │
└────────────────────────────────────────────┘
```

## 二、参数说明

| 参数 | 范围 | 作用 |
|---|---|---|
| **网格** | 4~128 px | 拖拽时的吸附步长（仅编辑器，不参与渲染） |
| **形状** | 矩形 / 圆角矩形 / 梯形 / 椭圆 | 四种形状循环切换 |
| **DPI** | 80~480 | UI 元数据，记录这块图层按什么密度设计 |
| **边框** | 0~40 px | 形状最外圈压暗成实线（描边效果） |
| **四角圆角** | 0~120°（夹到短边一半） | 四个角可独立设置，做出非对称形状 |
| **梯形上沿/下沿** | 0~300 px | 梯形上/下边的内缩量；上下不同 = 透视梯形 |
| **羽化** | 0~96 px | 边缘 alpha 从 0 渐变到 255 的宽度 |

**拖拽**：按住预览区里的图层拖动整体位置；按住右下角绿色圆点拖动改尺寸。松手按网格吸附并即时下发。

## 三、实现链路

```
LayerEditorActivity（Java）
   │ 拖动/滑杆 → LayerConfig
   │              ↓ toText() key=value
   │         /data/local/tmp/dcapd2.layer   ← 本机 adbd(root) 写入
   ▼
dcapd2（native，每 500ms 查 mtime）
   │ 变了 → dc_layer_load_file() → dc_layer_build()  重建遮罩
   ▼
每帧：画完内容 → dc_layer_apply()  把形状外 alpha 压 0 / 羽化预乘 / 边框压暗
   ▼
图块差量 → LZ4 → TCP 8444 → CP dashcastd → wl_shm ARGB8888 → ivi layer 99
   ▼
Weston 合成：形状外透出原厂仪表，形状内显示投屏内容
```

**为什么能"边调边看"**：`dashcastd` 和 `dcapd2` 的 TCP 不断，`dcapd2` 只是重建内存里的遮罩表，图层和连接都不动。实测参数一改，500ms 内仪表上就变。

## 四、配置文件格式

`/data/local/tmp/dcapd2.layer`，key=value 文本：

```ini
version=1
enabled=1            # 0 = 关闭（全屏不透明，旧行为）
canvas_w=1920
canvas_h=532
x=60                # 图层矩形（画布坐标）
y=40
w=1800
h=452
grid=32             # 仅编辑器用
shape=1             # 0=矩形 1=圆角矩形 2=梯形 3=椭圆
dpi=160             # 仅元数据
border=8
r_tl=90             # 四角圆角
r_tr=90
r_bl=90
r_br=90
trap_top=0          # 梯形上/下沿内缩
trap_bot=0
feather=60          # 羽化宽度
```

**手改这个文件也能生效**（不用开 App），`dcapd2` 会检测 mtime 自动重建。

## 五、关键实现细节（改代码前必读）

### 5.1 必须 premultiply

Wayland 的 `WL_SHM_FORMAT_ARGB8888` 是**预乘格式**。只改 alpha 不改 RGB，羽化边缘会发亮/串色：

```c
p[0] = (uint8_t)(((int)p[0] * a) / 255);
p[1] = (uint8_t)(((int)p[1] * a) / 255);
p[2] = (uint8_t)(((int)p[2] * a) / 255);
p[3] = a;
```

形状外（alpha=0）必须把 RGB 也清 0，否则合成器会透出脏色。

### 5.2 性能：不能在 apply 里算距离

`shape_distance()` 含 `sqrtf`。1920×532 = 102 万像素 × 30fps 逐像素调用会拖死 CP 那颗 2 核 SoC。

所以拆成两段：
- `dc_layer_build()`（配置变化时跑一次）→ 生成 `w×h` 的 alpha 表
- `dc_layer_apply()`（每帧跑）→ 只查表 + 乘法，**全不透明像素直接 continue**

边框描边也是同理：build 阶段把最外 `border` 圈标记成 `254`，apply 阶段见到 254 就压暗，不重算距离。

### 5.3 遮罩尺寸 vs 画布尺寸

`dc_layer_build()` 生成的 alpha 表只有图层矩形大小（如 1800×452），不是整块画布。`dc_layer_apply()` 通过 `(off_x, off_y)` 定位到画布里的偏移。这样内存和遍历量都小得多。

### 5.4 H.264 档没有 alpha

H.264 是 4:2:0，**格式决定没有透明通道**。切到 H.264 档后：
- 形状外的透明区变成**黑块**，盖住原厂仪表
- 圆角/羽化/边框全部失效

所以编辑器里明确标注了这条。**要用形状遮罩，必须留在 BGRA+LZ4 档。**

### 5.5 与 CP 侧的配合

CP 侧 `dashcastd` **一行都不用改**：
- `wl_shm` 用的是 `ARGB8888`，本来就带 alpha
- 图块粘贴是整行 `memcpy`（含第 4 字节），alpha 原样保留
- `blank_frame()` 提交全 0（全透明）的逻辑恰好也符合这套语义

## 六、真机验收（e04-p171）

### 6.1 遮罩生成与热重载

```
图层遮罩生效: shape=1 矩形=40,20 1840x492 圆角=40/40/40/40 梯形=0/0 羽化=24 边框=4
画布已按遮罩初始化：形状外透明（1920x532 画布，图层 40,20 1840x492）

图层遮罩生效: shape=1 矩形=60,40 1800x452 圆角=90/90/90/90 梯形=0/0 羽化=60 边框=8
```

进程未重启、TCP 未断、图层未重建 —— 仪表上直接变。

### 6.2 alpha 通道取证

`DC_DUMP_ALPHA=1` 时 `dcapd2` 会落 `/data/local/tmp/dc_alpha.ppm`（灰度图，白=不透明、黑=透明），用于隔着车机验证遮罩是否真的写进画布：

| 参数 | alpha 图表现 |
|---|---|
| 圆角 40 / 羽化 24 / 边框 4 | 小圆弧 + 窄过渡带 + 细暗线 |
| 圆角 90 / 羽化 60 / 边框 8 | 大圆弧 + 宽过渡带 + 粗暗线 |

两组都正确 —— 圆角、羽化、边框在 alpha 上都如实呈现。

### 6.3 形状正确性

离屏渲染 10 组参数（直角/圆角/非对称圆角/梯形/斜梯形/羽化24/羽化48/边框/椭圆/全参数组合），形状全部正确。

> 修过一个 bug：梯形距离场的左右边界判断写反，早期版本渲染成窄条。见 `layer_mask.c` 的 `LAYER_SHAPE_TRAP` 分支。

## 六之二、内容如何跟着形状走（v2.9.1）

**问题**：早期版本内容按整块画布等比居中（`453,0 1013x532`），遮罩一放大，
形状内就出现一圈黑边 —— 底部那块黑色没有投屏内容，看着像"没铺满"。

**修法**（三处，缺一不可）：

1. **映射跟随遮罩**：`recompute_dst()` 不再写死信箱矩形，遮罩一变就重算。
   `fit=0`（默认）时内容**拉伸铺满**遮罩矩形，尺寸严格等于 `w × h`；`fit=1` 才等比居中。
2. **遮罩外必须透明**：`dc_layer_clear_outside()` 每帧把矩形外的像素清成
   `alpha=0 且 RGB=0`。不清的话形状缩小后外面会残留上一帧旧画面；
   清了合成器才会把**原厂仪表透出来** —— 这就是"黑边的地方恢复原有的样子"。
3. **画布初值**：有遮罩时不要预填 `alpha=0xFF`，保持 `memset(0)` 的全透明初态。

**真机验证**：

```
画面映射: 源 1280x720 → 画布 700,40 1100x452（铺满遮罩）   ← 尺寸=遮罩矩形，无黑边
alpha 图:  矩形内纯白(255)/矩形外纯黑(0)                  ← 外面透出原厂仪表
CP 侧:     提交 24~28fps（累计丢 0）                      ← 推流正常
```

cfg 新增 `fit` 字段（编辑器「填充：铺满 / 等比」按钮可切）：

| fit | 行为 |
|---|---|
| 0（默认） | 拉伸铺满遮罩，不留黑边（视频轻微变形，但面积全用上） |
| 1 | 等比缩放、遮罩内居中，比例不符处留透明 |

> 铺满 vs 等比是取舍：铺满无黑边但画面会横向拉伸（源 1280×672 → 1100×452 比例 1.9 → 2.43）；等比不变形但留边。默认给铺满，因为用户诉求是"形状里全是我要的内容"。
## 六之三、H.264 档也能跟随遮罩（v2.9.1 核心）

**问题**：H.264 是 4:2:0，**格式上没有 alpha**。靠透明通道挖洞的做法在该档必然失败，
遮罩外的"透明区"会渲染成黑色块，把原厂仪表盖住。

**解法：改用几何约束，把 ivi 图层本身缩到遮罩矩形。**

这台 CP 的 `LayerManagerControl` 支持：

```sh
LayerManagerControl set layer 99 destination region <x> <y> <w> <h>
```

实测效果（关键证据）：

```
改前: destination region: x=0,   y=0,  w=960, h=266
执行: set layer 99 destination region 1000 60 880 420
改后: destination region: x=1000, y=60, w=880, h=420
       source region 不变 → 合成器把内容缩放填充到新矩形
```

**图层只在这块矩形内绘制，矩形外合成器根本不画 → 原厂仪表自然显露。**
这条路径与 alpha 完全无关，所以：

| 档位 | 遮罩外露原厂仪表的方式 |
|---|---|
| BGRA+LZ4 | ① 图层矩形（几何）+ ② alpha（圆角/羽化） |
| H.264 | **只有图层矩形**（几何）—— 圆角/羽化仍不可用 |

### 为什么不改 dashcastd（重要设计决策）

一开始想把矩形塞进握手协议、由 CP 侧 `dashcastd` 自己设置。这条路走不通，原因是：

- CP 只有车机内网可达，宿主机进不去
- 车机→CP 只能靠 App 的 SSH 通道，dropbear 的 exec 长度限制让 700KB 二进制
  传输极不可靠（分片被截断 → 远端 md5 对不上，这个 bug 之前一直静默失败）
- 为了加一条 `destination region` 去换掉整个 536KB 二进制，性价比极低

**最终方案：`destination region` 从 App 外部下发。** 二进制一行都不用动，
`CpManager.setLayerRect()` 直接走已有的 SSH 通道执行那条命令。

### 三层同步（缺一不可）

编辑器改参数 → `LayerConfig.pushAsync()` 一次做完三件事：

1. 写 `/data/local/tmp/dcapd2.layer` → `dcapd2` 重建遮罩（决定内容画在哪、alpha 形状）
2. `cp.setLayerRect(x,y,w,h)` → CP 把 ivi 图层缩到同一矩形（决定图层占屏哪块）
3. 存 SharedPreferences → 重启 App 记得住

只做 1：H.264 档遮罩外是黑块。
只做 2：BGRA 档的圆角/羽化失效。
**1+2 才是完整效果。**

### 兼容性兜底

`ensureDashcastd()` 改为 **md5 不一致不再阻断**：

```
推送失败，但 CP 上已有可执行的 dashcastd —— 继续使用旧版
（图层矩形由 setLayerRect 外部设置，功能不受影响）
```

因为图层矩形已不依赖 CP 侧二进制，旧版 `dashcastd` 照样能用。
宁可跑旧版也不让投屏起不来。

同时新版 `dcapd2` 默认**不发**图层矩形（`DC_SEND_LAYER_RECT=1` 才发）——
避免 CP 上旧版 `dashcastd` 把多出来的 20 字节当成帧头读，导致协议错位。

## 七、已知限制

1. **H.264 档不可用**（无 alpha，形状变黑块）—— 格式决定，非实现问题。
2. **H.264 档圆角/羽化不可用**：该档靠图层矩形做到"遮罩外露原厂"，但 4:2:0 无 alpha，圆角边和羽化渐变做不出来（只能是硬边矩形）。BGRA 档才有完整形状。
3. **形状能力上限**：目前是 4 种基本形状 + 四角独立圆角 + 梯形内缩 + 羽化 + 边框。**不支持任意路径/贝塞尔曲线**，也不支持多图层叠加（只有一个图层 99）。
3. **编辑器滑杆的自动化测试受限**：`adb input swipe/tap` 不会触发 Android SeekBar 的完整触摸序列，所以做不到脚本化拖滑杆验证。功能本身正常（手指操作没问题），只是自动化验证走了"直接改配置文件"这条路。
4. **遮罩只在 `dcapd2` 侧生效**：旧的 `dcap_lib.so` / `DashcastSenderService` 那条死路径没有接入（它已不在主线）。
5. **alpha 8bit 量化**：圆角/斜边在极高对比度下可能有轻微锯齿，1920×532 面板上看不出来。
