# Dashcast 技术档案

> 车机中控（AP）→ 仪表盘（CP）单向投屏系统。
> 本文档记录架构、关键设计决策、以及排查过程中踩过的所有坑。

## 一、系统架构

```
┌─────────────────────┐         ┌──────────────────────┐
│  车机中控 AP         │         │  仪表盘 CP            │
│  Android 11, root    │         │  Linux aarch64        │
│                      │         │  Weston + ivi-shell   │
│  ┌────────────────┐  │         │  ┌─────────────────┐  │
│  │ Dashcast App   │  │         │  │ dashcastd       │  │
│  │ (用户界面)      │  │  SSH    │  │ (C 守护进程)     │  │
│  └───────┬────────┘  │────────▶│  └────────┬────────┘  │
│          │ adbd      │         │           │           │
│  ┌───────▼────────┐  │  TCP    │  ┌────────▼────────┐  │
│  │ dcapd2         │  │  8444   │  │ layer 99        │  │
│  │ (抓帧+编码)     │──┼────────▶│  │ (ivi 图层)       │  │
│  └────────────────┘  │         │  └─────────────────┘  │
│                      │         │  DSI-1 1920×532       │
└─────────────────────┘         └──────────────────────┘
```

### 核心约束（硬性）

| 约束 | 原因 |
|---|---|
| **CP 上不留任何持久化文件** | CP 的 `/run` 是 tmpfs，重启即丢；车规要求 CP 不留痕 |
| **CP 重启自动恢复原厂** | 所有改动必须能在 CP 重启后自愈 |
| **不修改车机系统 App** | 只读探测，所有改动在 dashcast 内部 |

## 二、画布与坐标系（最容易出错的地方）

这是**所有重影问题的根源**，务必理解清楚。

### 三个坐标系

```
① AP 抓帧坐标    (capW × capH)   例: 1280×720
        ↓ captureScreen crop
② AP 画布坐标    (1920 × 532)    = 仪表全屏尺寸，固定
        ↓ 编码 + 传输
③ CP 图层坐标    destination region + source region
```

### 关键规则

**AP 端 dcapd2 的行为**：
- 画布固定 `1920×532`
- `blit` 把画面画进**遮罩矩形**（如 `800,64 896×436`）
- 画布其余位置 `memset` 成全透明 `(0,0,0,0)`

**CP 端 destination region 必须按编码档算**（见 `LayerGeometry.java`）：

| 编码档 | destination | source | 效果 |
|---|---|---|---|
| **BGRA+LZ4** | `0,0 1920×532`（整屏） | `0,0 1920×532` | 1:1 零缩放，画布透明处透出原厂仪表 |
| **H.264** | 遮罩矩形 | 遮罩尺寸 | 图层本身缩进那块，旁边露出原厂 |

### ⚠️ 致命错误（会导致"两个画面叠加"）

```
AP:  画面画在画布 800,64 处（896×436）
CP:  destination = 800,64 896×436, source = 0,0 1920×532
     ↓
合成器把【整块 1920×532 画布】压缩到 896×436
     ↓
画布上那个正常画面 → 被压成 1/4 大小，跑到 destination 一角
     ↓
用户看到：正常画面 + 缩小副本 = 重影
```

**三处调用 `setLayerRect` 的地方都必须走 `LayerGeometry`**：
1. `MainActivity.saveMask()` —— 点"保存并应用"
2. `LayerConfig.pushAsync()` —— 编辑器保存
3. `MirrorController.syncLayerRectAsync()` —— 8 秒保活

漏掉任何一处，对应操作就会触发重影。

## 三、ivi-shell 图层管理

### surface 双挂载问题

**ivi-shell 语义**：一个 surface **可以同时属于多个 layer**，且
`add surface to layer` 是**追加**，不是迁移。

**事故现象**：
```
layer 10（原厂图层）surface render order: 4711, 9001
layer 99（投屏图层）surface render order: 9001
```
同一个 surface `9001` 同时挂在两层 → 仪表出现两份画面。

**根因时序**：
```
init_wayland():  ivi_application_surface_create(9001) + wl_surface_commit()
                 → ivi-shell 自动挂到默认层（layer 10）
setup_layer():   只做 add 到 99，从不摘 10 → 一直双挂
```

**正确顺序**（实测验证）：
```c
create layer 99;
add surface 9001 to layer 99;      // 先挂到目标层
detach_surface_from_all_layers();  // 再摘掉其他所有层
```

反过来（先摘后 add）没用：`add` 之后 ivi-shell 仍保留 10 上的登记。

**实测结论**：`remove surface` 有效，且 `wl_surface_commit` 不会把 surface 挂回去
（手写 remove 后等 5 秒 / 150 次 commit，验证无回弹）。

### 其他 ivi 要点

| 命令 | 注意 |
|---|---|
| `set screen 0 render order 10,99` | **必须逗号分隔**。空格会 `Interpreter error` 整条被拒 |
| `create layer` | 默认 `visibility = 0`，必须显式 `set layer 99 visibility 1` |
| `destroy layer 99` | **不会清理**它挂过的 surface，surface 会掉回之前所属的层 |

## 四、编码档差异

| 项目 | BGRA+LZ4 | H.264 |
|---|---|---|
| alpha 通道 | ✅ 有 | ❌ 无（4:2:0 YUV） |
| 编码方式 | 图块增量 + LZ4 | MediaCodec 硬编 |
| 带宽 | ~2543 KB/s | **~49 KB/s**（快 52 倍） |
| 形状遮罩 | ✅ 圆角/梯形/椭圆/羽化 | ❌ 强制矩形 |
| 重影风险 | 高（增量编码） | 低（整帧覆盖） |

### H.264 为什么不能有圆角

`h264rx.c` 解码出来每个像素都是不透明的：
```c
row[i] = 0xFF000000u | (r << 16) | (g << 8) | b;
```
遮罩的透明区域到仪表上就是**黑色**——这就是黑边。

**修复**：H.264 档 `layer_mask_reload` 时强制 `shape = LAYER_SHAPE_RECT`。

### BGRA 的增量编码重影

**问题链**：
```
① 图块逐个解压、逐个写进 frame_buffer
② 第 k 个图块 LZ4 解压失败 → frame_ok=0，break
③ 前面 k-1 个块【已经写进去了】，但这一帧不 commit
④ 下一帧 AP 只发"与自己 prev 不同"的块
⑤ 那 k-1 个块在 AP 的 prev 里是旧值 → 永远不重发
⑥ frame_buffer 里留下脏块 → 之后每帧 commit 都糊上屏 = 重影
```

**修复**：坏帧时 `break` 断开 TCP，让 AP 的 `enc_connect` 重置 `prev` +
`force_full` 重发整帧。代价 ~1 秒闪一下。

## 五、已修复的 Bug 清单

### 🔴 严重（会导致崩溃/完全不可用）

| # | 问题 | 位置 | 修复 |
|---|---|---|---|
| 1 | `applyImmersive` 在 DecorView 未建时调 `getInsetsController` → **NPE 闪退** | MainActivity | 挪到 setContentView 之后 + `post` + try-catch |
